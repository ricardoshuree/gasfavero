### 3.4. Regra de negócio grande: "chamado nunca fica em limbo"
Sessão de mapeamento de cenários com o Ricardo (cenário 1: chamado aberto, cenário 2: convite direto) revelou um buraco real: o endpoint `recusar` matava o chamado (`status='recusada'`) sem reatribuição automática -- se ninguém soubesse, o chamado sumia pra sempre.

**Decisão final**: motorista NUNCA mais recusa de um jeito que muda o banco.
- Chamado **aberto**: "Recusar" no alerta é 100% LOCAL (só fecha a tela + para o alarme pro aparelho dele; não chama API nenhuma; chamado continua pendente pra qualquer outro)
- Convite **direto**: não tem opção de recusar em lugar nenhum -- só Aceitar. Quem gerencia é o atendente.
- `recusar_demanda_venda` (backend) continua existindo por retrocompatibilidade, mas ganhou proteção reforçada (`action="delete"`, só atendente/gerente) -- nunca mais chamado pelo app do motorista.

### 3.5. Backend novo -- migration + endpoints (Fase 1+2 do plano)
**Migration** `k6l7m8n9o0p1`: campo `disponivel: bool` em `User`, `DEFAULT TRUE` (proposital -- rollout seguro, ninguém some do combo de despacho no dia 1).

**Endpoints novos** (`backend/app/api/routes/delegacao.py`):
- `PATCH /demandas-venda/{id}/cancelar` -- de QUALQUER estado ativo (pendente/aceita), preenche `finalizada_em` (mesmo campo do "concluir" -- `status` diferencia os dois motivos agora). Bloqueia 400 se já `concluida`/`cancelada`.
- `PATCH /demandas-venda/{id}/reatribuir` -- só de `pendente`, troca `motorista_id` (ou `None` = reabre aberto), MESMO REGISTRO (não cria novo), volta status pra `pendente`.
- `PUT /motoristas/{id}/disponibilidade` -- toggle persistido de verdade
- `GET /motoristas/disponibilidade` -- lista todos com role Motorista + status

**Proteção de permissão sem módulo RBAC novo** (elegante, vale lembrar): cancelar/reatribuir usam `action="delete"` do módulo `delegacao` já existente. Motorista tem Ver+Editar mas NUNCA Apagar -- fica bloqueado automaticamente, sem precisar criar módulo/matriz nova.

**Testado e confirmado** (local E produção, via fetch direto): criar chamado → cancelar → `status` vira `cancelada` ✓. Criar direcionado ao Loris → reatribuir pro Ricardo Motorista → `motorista_nome` muda, `status` volta `pendente`, `respondida_em` zera ✓. Motorista tentando `/cancelar` → 403 confirmado ✓.

## 6. Armadilhas técnicas conhecidas (economize tempo, já resolvidas antes)

- **`alembic.exe` bloqueado pelo Device Guard do Windows**: sempre usar `uv run python -m alembic ...`, nunca `uv run alembic ...`.
- **MCP `write_file` quebra `.json`**: injeta comentário de rastreabilidade que quebra parsing JSON. Instalar pacotes via `npm install <pacote>` no terminal (o npm reescreve o JSON sozinho).
- **`.css` bloqueado por extensão no MCP** (Ricardo tentou habilitar no config.yaml, não pegou em tempo real -- precisa reiniciar o servidor MCP). Todo estilo do `frontend-motorista` está inline (objetos JS) por causa disso.
- **Editar env vars do Railway via Raw Editor com automação de browser é arriscado** -- já causou um crash de produção nesta sessão (aspas soltas). Prefira terminal (`railway run`) ou pedir pro Ricardo digitar.
- **Rota nova no TanStack Router quebra o build**: `npm run build` roda `tsc` ANTES do `vite build`, e é o Vite (plugin `@tanstack/router-plugin`) que gera `routeTree.gen.ts`. Se criar arquivo de rota novo, rodar `npm run dev` uma vez primeiro (gera o arquivo), Ctrl+C, DEPOIS `npm run build`.
- **Terminal Windows, porta em uso**: `Get-NetTCPConnection -LocalPort 5175 -State Listen | Select-Object -ExpandProperty OwningProcess | ForEach-Object { Stop-Process -Id $_ -Force }`
- **Regenerar cliente OpenAPI do frontend principal** (depois de mudar o backend):
  ```powershell
  cd C:\project-claude\erp-gasfavero\backend
  $env:FASTAPI_ENV="development"
  uv run python -c "import app.main; import json; print(json.dumps(app.main.app.openapi()))" > ../openapi.json
  cd ..
  Move-Item -Force openapi.json frontend/openapi.json
  cd frontend
  npm run generate-client
  ```
- **Backend/Frontend locais precisam ser reabertos manualmente toda sessão** -- Ricardo costuma fechar os terminais entre sessões. Sempre confirmar se `uvicorn`/`npm run dev` estão rodando antes de pedir teste.
